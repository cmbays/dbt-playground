## Design Decisions

Based on user requirements:

| Question | Decision |
|----------|----------|
| SCD Type 2 for patients? | **Yes** - Track patient history with valid_from/valid_to |
| Full payers dimension? | **Yes** - Create `dim_payers` with all attributes |
| Aggregate fact tables? | **Yes** - Monthly and yearly aggregates |
| Date range for dim_date | **1909-01-01 to 2025-12-31** (data spans 1909-2020) |

### 5. dim_patients (SCD Type 2)

**Purpose**: Patient dimension with history tracking

**Source**: `stg_synthea__patients`

**SCD Type 2 Implementation**:

- `valid_from`: Date record became current
- `valid_to`: Date record was superseded (NULL = current)
- `is_current`: Boolean flag for current record
- `patient_key`: Surrogate key (unique per version)

**Columns**:

| Column | Type | Source |
|--------|------|--------|
| patient_key | INTEGER | row_number() surrogate |
| patient_id | VARCHAR | Natural key (UUID) |
| first_name | VARCHAR | first_name |
| last_name | VARCHAR | last_name |
| full_name | VARCHAR | Derived: first_name \|\| ' ' \|\| last_name |
| name_prefix | VARCHAR | name_prefix |
| name_suffix | VARCHAR | name_suffix |
| birth_date | DATE | birth_date |
| death_date | DATE | death_date (nullable) |
| age_years | INTEGER | Derived: current age or age at death |
| is_deceased | BOOLEAN | Derived: death_date IS NOT NULL |
| gender | VARCHAR | gender |
| race | VARCHAR | race |
| ethnicity | VARCHAR | ethnicity |
| marital_status | VARCHAR | marital_status |
| address | VARCHAR | address |
| city | VARCHAR | city |
| state | VARCHAR | state |
| county | VARCHAR | county |
| zip_code | VARCHAR | zip_code |
| latitude | DOUBLE | latitude |
| longitude | DOUBLE | longitude |
| healthcare_expenses | DECIMAL | healthcare_expenses |
| healthcare_coverage | DECIMAL | healthcare_coverage |
| valid_from | DATE | SCD2: Record start date |
| valid_to | DATE | SCD2: Record end date (NULL = current) |
| is_current | BOOLEAN | SCD2: Current record flag |
| _loaded_at | TIMESTAMP | Metadata |

**Note**: For initial load, all records will have:

- `valid_from` = birth_date (or min encounter date)
- `valid_to` = NULL
- `is_current` = TRUE

## Testing Strategy

### Required Tests Per Model

| Model | Tests |
|-------|-------|
| All dimensions | unique + not_null on surrogate key |
| All dimensions | unique on natural key |
| All facts | unique + not_null on surrogate key |
| fct_encounters | relationships to all dimensions |
| fct_clinical_events | relationships to dim_patients, fct_encounters |
| Aggregates | unique on grain columns |

### Referential Integrity Tests

```yaml
# Example for fct_encounters
- relationships:
    to: ref('dim_patients')
    field: patient_id
    config:
      where: "is_current = true"
```

### Grain Tests

```yaml
# Ensure no duplicate grains
- dbt_utils.unique_combination_of_columns:
    combination_of_columns:
      - encounter_id
```

## Risks & Mitigations

| Risk | Mitigation |
|------|------------|
| Large dim_date (117 years) | Pre-generate with dbt_date, test performance |
| SCD Type 2 complexity | Start with initial load pattern, defer change tracking |
| fct_clinical_events UNION performance | Consider materialization as table |
| Circular dependencies | Ensure DAG is acyclic before implementation |

## Commands Reference

```bash
# Build dimensions first
dbt run --select dim_date dim_organizations dim_payers

# Build dependent dimensions
dbt run --select dim_providers dim_patients

# Build facts
dbt run --select fct_encounters fct_clinical_events

# Build intermediate and aggregates
dbt run --select int_encounters__enriched int_patients__with_conditions
dbt run --select fct_encounters_monthly fct_encounters_yearly

# Full build with tests
dbt build --select tag:marts

# Test referential integrity
dbt test --select tag:marts

# Generate docs
dbt docs generate && dbt docs serve
```
